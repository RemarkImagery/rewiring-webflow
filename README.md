# rewiring-webflow

React code components for the Rewiring Aotearoa Webflow site (rewiring.nz), built with
`@webflow/react` and shared to the workspace as the **Rewiring Components** library
(`867a2cd5-80de-491a-bdfc-b6b48ef4ba7d`).

```bash
npm install
npm run dev          # http://localhost:3000 - harness pages, see below
npm run typecheck    # tsc
npm test             # vitest (jsdom)
printf 'y\n' | npx webflow library share --skip-update-check   # publish the WHOLE library
```

Every component is two files: `Foo.tsx` (the React implementation, scoped CSS in a `<style>`
generated with `useId()`) and `Foo.webflow.tsx` (the `declareComponent` registration - the props a
designer sees). Only `*.webflow.tsx` files are picked up by `webflow.json`.

## Regional reports — which component is which

The "Electrifying [Location]" pages at `rewiring.nz/regional-reports/<slug>` are rendered by
components in `src/components/RegionReport/`, from data bundled at build time.

| Component | Role | Status |
|---|---|---|
| `RwRegionReport` | The whole report in one component. Inlines its own `<style>`. | **Live** on rewiring.nz (verified 3 Sep 2026: one island, stylesheet inside its shadow root) |
| `RwReportIntro` / `RwReportBills` / `RwReportMachines` | The same report as three CMS-bindable chunks, so a story collection can slot between Bills and Machines. | Built and tested; not currently placed on the live site |
| `RwLocalStoriesSimple` / `RwCommunitySimple` / `RwRegionFooterSimple` | Plain link-out sections used while the CMS-bound versions are finished. | **Live** |
| `RwLocalStoryCard`, `RwCommunityCard`, `RwCommunityGroups` | CMS-bound story card, community card, and the groups carousel + map. | Available; groups map needs the CMS embed described in its description |
| `RwRegionFooter` | Two-card footer with the per-location PDF link. | Available (the Simple footer is live) |
| `RwRegionPicker`, `RwRegionIndex`, `RwRegionIndexPage` | Type→location dropdown, directory columns, and the whole `/regional-reports` landing page. | **Live** (index page) |

Every report component takes a `districtSlug` prop; blank means "read the last URL segment".
A slug that matches nothing in the bundle renders a visible **No report data** notice on a
`/regional-reports/…` page rather than another region's figures (the Designer canvas still
shows Dunedin so the layout is populated).

### Generated files — never hand-edit

| File | Generated by (in `rewiring-district-pages`) |
|---|---|
| `districtData.ts` | `build/build_components.py` — the 83-location data bundle (~3 MB, parsed on every page; the escape hatch is per-slug JSON on regional-reports.pages.dev, fetched at mount) |
| `reportContent.ts`, `reportTabs.ts` | `build/build_components.py` — the page template, CSS and national chart fallbacks |
| `reportEditable.ts` + the `BEGIN/END generated text props` blocks in the four report `.webflow.tsx` files | `build/build_editable_text.py` — every heading and paragraph as an editable prop |

Regeneration order, run from the sibling repo after its `build_preview.py`:
`python build/build_components.py && python build/build_editable_text.py`, then `npm run typecheck && npm test` here.

### The shadow-root rule

Webflow renders each code component inside its own **shadow root**. Anything that relies on the
document — `getElementById`, a stylesheet in `<head>`, a fragment link — does nothing on the live
site. So: report CSS is injected into the component's own root (`ensureReportCss(root)`), jump
links resolve their targets by walking every shadow root (`installAnchorNav`), and components are
tested in harnesses that mount them with `attachShadow`:

- `/region-report-test?slug=x` — the monolith
- `/region-chunks-test?slug=x` — the chunk trio stacked as a designer would
- `/region-anchor-test?slug=x` — each chunk in its own shadow root; jump-link tests
- `/region-simple-test`, `/region-text-test`, `/region-index-test`

## Releasing

1. `npm run typecheck && npm test`.
2. `printf 'y\n' | npx webflow library share --skip-update-check` — publishes every component in the
   library to the client's workspace. Say so before running it.
3. A designer accepts the library update in Webflow Designer and republishes the site — placed
   instances do not update on their own.
4. Verify the live pages: `python tests/e2e/live_report_check.py` in `rewiring-district-pages`
   (walks the shadow roots; a light-DOM check passes vacuously).

## Environment

- `.env` (git-ignored): `WEBFLOW_WORKSPACE_API_TOKEN` — the workspace token the Webflow CLI uses
  for `library share`. `npx webflow login` creates it.
- The Mapbox token in `RwCommunityGroups.tsx` is a public `pk.` token (Oliver's account), stored
  base64 only because GitHub's secret scanner false-positives on it.

## Conventions

See `CLAUDE.md`. In short: colours are Text props (the SDK has no Color prop); every Webflow Link
prop reads `"#"` when blank, so treat `#` as unset; no shared stylesheet — every component carries
its own scoped CSS.
